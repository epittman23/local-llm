# Assistant tools: code interpreter, web search, retrieval, memory

The services and models behind three of the assistant's tools, added on
2026-10-24. The services run from `infra/docker-compose.yml` and start and
stop with `make backend`. The settings that point the app at them live in
the app's database (Admin Settings), not in a repo file.

## Code interpreter: the sandbox

The code interpreter runs each chat's code in its own Kata Containers
microVM, with a `/workspace` that persists for the chat. It is the only
engine: the Jupyter and Pyodide engines this app once had were removed
(2026-11-13, PR #889), and `sandbox` is the only value the engine settings
accept. The host setup, images, operations and tests are in
[sandbox.md](sandbox.md); the design is in
[the proposal it was built from](../history/sandbox-code-interpreter.md).
It needs no service from the Compose file beyond the package mirror that
`make backend` starts.

- **What the model gets.** With native function calling, four tools:
  `bash` (a command, 1 to 300 seconds, the default from the admin's
  setting), `view`, `write_file` and `str_replace`, all confined to
  `/workspace`. On the tag path (legacy function calling), each
  `<code_interpreter>` block runs as a Python file in the same sandbox. The
  prompts are `CODE_INTERPRETER_SANDBOX_PROMPT` and
  `CODE_INTERPRETER_SANDBOX_TAG_PROMPT` in `config.py`.
- **Files.** The chat's attachments are in `/workspace/uploads`, read-only.
  Whatever the code leaves in `/workspace/outputs` is attached to the
  reply and shown under it: images, a sandboxed frame for HTML, PDF page
  previews, highlighted text and CSV tables, and a download link for
  everything.
- **State.** Files, installed packages and data persist for the whole chat
  (a fixed 10 GiB per workspace); nothing keeps running between calls. An
  idle sandbox stops after 30 minutes and starts again on the next call.
  A workspace unused for 7 days, or one standing in the way of a new
  chat's past the per-user cap (20), is deleted only when the user
  answers the app's keep-or-remove dialog.
- **Packages.** No internet: `pip install` reaches only the reviewed
  wheelhouse (`make wheelhouse`), and the images carry the scientific
  Python stack, R, TeX Live and Node.js tooling. The names and versions
  of the packages a chat imports, installs or lacks are recorded for the
  admin's report (never its code or data; sandbox.md "Package
  telemetry").
- **Run button.** A Python block in a reply has Run, which runs it in the
  chat's sandbox, while code execution and the code interpreter are both
  switched on and for a user
  with its permission (admins always have it).

**Settings** (Admin Settings > Code Execution): there is no engine choice.
The page holds the sandbox fields (default image, command timeout, how
many run at once, idle minutes, retention days, workspaces per user) and a
status line saying whether the host can run sandboxes. The host needs
KVM, Kata registered as `kata-clh`, the images (`make sandbox-images`) and
the wheelhouse; see [sandbox.md](sandbox.md). A stored engine value
naming a removed engine (an environment variable naming one is ignored
with a warning) leaves the interpreter off until
the page saves `sandbox`; the migration of 2026-11-13 (revision
`807e3e98e4af`) already set the stored ones.

## Web search: SearXNG

The `searxng` service is `searxng/searxng:2026.10.17-1c10abe2d`, on
`127.0.0.1:8080`, with its secret from `infra/.env` (`SEARXNG_SECRET`,
generated by `make backend` when missing). `infra/searxng/settings.yml`
holds only what differs from SearXNG's defaults: JSON output on, which the
backend needs, and the limiter off, which needs a Redis of its own.

**What it does and does not keep private.** SearXNG needs no API key and
no account, and sends no cookies. But it is a metasearch engine: each query
still goes to the upstream engines it asks (Google, Bing, DuckDuckGo and
others), from this machine's IP address. Those engines see the query,
without knowing which user or chat it came from. Upstream engines also
rate-limit it now and then. On 2026-10-24 a query returned 20 results
while Brave and DuckDuckGo did not answer.

**Settings** (Admin Settings > Web Search): turn web search on, set the
engine to `searxng` and the query URL to
`http://127.0.0.1:8080/search?q=<query>`.

**Speed.** SearXNG answers in a second or two, but a web search in chat
also fetches each result page and embeds it. On 2026-10-24, five results
took 107 s end to end on this laptop's CPU (embedding with bge-m3, below).
Fewer results (`WEB_SEARCH_RESULT_COUNT`), or "Bypass Embedding and
Retrieval", which passes the fetched pages to the model whole, are the
levers. Neither has been measured yet.

## Knowledge retrieval

Since 2026-10-24 knowledge bases use:

| Role | Model | Size | Notes |
|---|---|---|---|
| Embeddings | `BAAI/bge-m3` | about 2.2 GB | multilingual, 1024 dimensions, up to 8,192 tokens |
| Reranker | `BAAI/bge-reranker-v2-m3` | about 2.2 GB | a cross-encoder that scores each candidate passage against the query |

They replace `sentence-transformers/all-MiniLM-L6-v2` (384 dimensions,
English only, about 0.1 GB) with no reranker. Both run on the CPU (torch is
the CPU build) and load from the Hugging Face cache, since `make backend`
runs offline; see [dependencies.md](dependencies.md#offline-model-cache) for
downloading them.

Hybrid search is on, so each query is answered by keyword search and
vector search together. The top 5 candidates go to the reranker, and
the best 3 are kept (`TOP_K` 5, `TOP_K_RERANKER` 3).

On pgvector, with enriched texts off (the default), the keyword half is
Postgres full-text search, run natively
(`retrieval/vector/dbs/pgvector.py`'s `hybrid_search`), not BM25. Since
2026-11-08 (#347) it matches a chunk holding **any** of the question's
words, under the `english` text-search config: stop words are dropped
and words stemmed ("Settings" matches "set"), so "How do I rotate the API
key?" searches for `rotat | api | key`. It ranks with `ts_rank_cd` and
merges with the vector results by reciprocal rank at the BM25 weight
(`rag.hybrid_bm25_weight`, default 0.5). English rules apply to every
language, though `bge-m3` is multilingual. A question of only stop words
matches nothing; at weight 1, where vector search is otherwise skipped,
an empty keyword result falls back to vector search. The index behind it,
`idx_document_chunk_text_search_english`, is built at startup if missing,
so the first start after an upgrade indexes every existing chunk.

The vector column stays `vector(1536)`: the app pads shorter embeddings
with zeros, which leaves cosine similarity unchanged, so a 1024-dimension
model needs no migration. **Changing the embedding model later means
re-embedding every knowledge base**, since vectors from two models are not
comparable. The database held no knowledge, files or memories when this
model was chosen.

**Measured 2026-10-24** (this laptop's CPU; three one-paragraph files in
one knowledge base; queries worded unlike their answers):

| Query | Top hit | Reranker scores |
|---|---|---|
| "how do I compare before and after measurements on the same people?" | the paired t-test file | 0.979, 0.006, 0.000 |
| "smoothing a noisy daily series" | the rolling mean file | 0.820, 0.000, 0.000 |
| "when was the tower in France built?" | the Eiffel Tower file | 0.952, 0.000, 0.000 |

Each query took about 1.8 s. Loading both models offline took about 4 s
each.

**Settings** (Admin Settings > Documents): embedding engine "Default
(SentenceTransformers)" with model `BAAI/bge-m3`; hybrid search on;
reranking engine "Default (SentenceTransformers)" with model
`BAAI/bge-reranker-v2-m3`; top K 5, top K reranker 3.

## Memory background review

With memories on, the app can also review a chat every 10th user turn
and add or update memories from it (`memories.background_review.enable`,
`memories.review_interval_turns`). It is on since 2026-10-24. Three things
to know:

- **No page has a switch for it.** It is set through the admin config
  import (`POST /api/v1/configs/import` with
  `{"config": {"memories.background_review.enable": true}}`).
- **It only runs on chats with the memory feature on**, and it asks the
  chat's own model, so on OpenRouter each review is one more request
  carrying the last 16 messages.
- **Not yet seen working end to end.** The setting is stored, but no
  ten-turn chat has run since.
